# jatinmomaya.com: repo review and plan (2026-10-17)

Written after the bookshelf, photo book and cleanup work on `feature/bookshelf-home`.
Nothing here is done unless it says so. Photos staying in git for now is a decision, not a gap.

## What the site is now

- One screen: a bookshelf (reading now, objects, favorites). No scrolling at any size.
- Objects open a panel: Photographs (trips), Tennis, Writing, Work.
- A trip opens as a photo book, six frames a page, then a photo on a lit tabletop.
- Light and dark follow the device. Goodreads feeds the favorites shelf (`npm run favorites`).
- Next.js static export. Vercel serves the repo root. The root `_next/` and `*.html` are committed build output.

## Findings, ranked

### P0: before anything goes to production

1. **Export leaves stale pages live.** *(Fixed in code on 2026-10-17; takes effect on the next export. See below.)* `export-root.mjs` copies `out/` over the root and only wipes `_next/`.
   `products.html`, `photography.html`, `bookshelf.html`, `blog.html` (and their `.txt`), the starter SVGs and the
   root `textures/` stay in the repo root, so production would keep serving the old placeholder pages after the new
   build goes out. Fix: record what each export wrote in `.export-manifest.json` and delete files from the previous
   manifest that are not in the new one. Never touch files the manifest did not write (`docs/`, `design-prototype/`,
   `resume.pdf`).
2. **Photo originals exist only on this machine.** `personal-website/photos-src/` (about 97 MB) is git-ignored and
   has no backup. Back it up (cloud drive or an external disk) before adding more trips.
3. **The whole repo is public through the site.** Vercel serves the repo root, so `docs/`, `design-prototype/` and
   `personal-website/` (source, scripts, data) are downloadable at the site's URL. No secrets were found in `docs/`,
   but internal notes should not be public by accident.

### P1: scale and safety

4. **Committed build output.** Every export rewrites hashed files in `_next/` and re-copies photos into the root
   `photos/` (a second copy of what is in `personal-website/public/photos`). History grows with every deploy
   (.git is 32 MB now). Preferred fix: let Vercel build `personal-website/` itself (Root Directory setting), so
   nothing generated is committed, every branch gets a real preview, and stale pages cannot happen.
   This changes production, so it needs your approval and a preview first.
5. **No automated checks.** Add a GitHub Action on pull requests: lint, typecheck, build, `check:assets`,
   `export:check`. Add a data check for `books.json`, `favorites.json`, `writing.json` and the trip files
   (unique ids, allowed values, no empty required fields).
6. **No browser tests.** Add Playwright smoke tests for the things that broke today: home fits one screen at 5 sizes,
   no spine clipped, the book shows 6 per page, Escape closes layers in order, focus returns, no horizontal scroll.
   Add an axe accessibility pass.
7. **Caching and headers.** There is no `vercel.json`. Photos are not content-hashed, so re-encoding a photo keeps its
   URL. Until that changes, cache photos for a day with revalidation, not forever. Add basic security headers.
8. **Reading shelf is manual.** `books.json` has no sync. Extend the favorites script to the currently-reading shelf
   and run it on a schedule in GitHub Actions that opens a pull request (never commits to `main`).

9a. **Dependency advisories.** `npm audit` reports 5 issues (1 critical, 4 high): `next` 15.1.9 (dev-server and cache
    issues), `sharp` (libvips, used only locally on your own photos), `postcss`, `nanoid`, `source-map-js`. The
    published site is static files with no Next server, so the live site is not exposed to the `next` ones, but the
    dev machine and build are. Plan: bump `next` to the latest 15.x patch on its own branch, run `npm run verify`,
    and look at the result in the browser before merging. Add a weekly Dependabot pull request for the same.

### P2: polish and growth

9. **Writing.** The Writing object lists six "Lorem ipsum" drafts. Remove them before launch. When essays are real, put
   them in `src/content/writing/*.md`, render at build time at `/writing/<slug>`, add an RSS feed, and link the ones
   that live on Substack or Medium. The shelf panel keeps showing the newest few.
10. **Sharing and search.** Add a social preview image, `robots.txt`, a sitemap, `Person` structured data and a
    canonical URL. Today there is only a title and description.
11. **Third and later trips.** A trip is one JSON file plus photos (`npm run photos -- <id>`). Japan needs no code.
    The book assumes six frames a page; a trip with one or two photos still works. Trip order is newest first.
12. **Photos in git.** Warn at about 120 MB, fail at 200 MB (already in `check-assets`). Today: 14 MB. The move to
    object storage (R2 or Vercel Blob) only changes `photoUrl()`. Keep originals backed up either way.
13. **Tailwind and animejs.** Tailwind is used only by the resume page header; animejs only for two small
    animations. Both could go to cut the baseline JavaScript (106 KB shared). Low priority; measure first.
14. **Unused data.** `books.json` has 214 books and only the 4 reading are shown; 8 of the 12 cover files are unused.
    Keep as data, but a "full library" page is a future option if wanted.

### Done: export prune and manifest

`scripts/export-root.mjs` now removes files an earlier export wrote that the new build no longer makes, and saves
`.export-manifest.json` (the list of files it wrote). The first run uses a built-in list of the 18 known leftovers
(the four old pages, their `.txt` files, the starter images, the cork texture). `docs/`, `design-prototype/`,
`personal-website/`, `styles.css` and the manifest are never removed. `npm run export:check` lists what would go
without changing anything. Tested in a throwaway copy: legacy files removed, protected files kept, a dropped page
removed on the second run. It has not been run against the real repo root.

### Done: data checks and the pull-request check (item 5)

- `npm run check:data` validates `books.json`, `favorites.json` and `writing.json` (unique ids, allowed values,
  cover files exist, real posts have a date and link). It runs before every `export:root`. Tested against 8 seeded
  mistakes; all were caught.
- `npm run verify` runs the whole chain locally: lint, types, data, build, asset budgets, export dry run.
- `.github/workflows/checks.yml` runs the same steps on every pull request and on pushes to `main`. It reads the repo
  only: no secrets, no deploy. It has not run on GitHub yet; the first pull request will show whether it passes there.
- `sharp` is now an explicit dev dependency (the scripts imported it without declaring it).

## Panel notes (short)

- **Architecture:** the data-file model (one JSON per trip, lazy chunk per trip) scales well. The deploy model
  (committed build output) is the weak part (items 1, 3, 4).
- **Performance:** home is 116 KB first load; photo frames lazy-load with reserved color. No problems at 2 or 20 trips.
  At about 50 trips, add trip index pages.
- **Accessibility:** dialogs trap focus, Escape layers correctly, reduced motion respected, contrast checked in
  both themes. Still to do: automated axe run, screen-reader pass on the vertical spine text.
- **Security and privacy:** photos have EXIF stripped and a check enforces it. No cookies; Vercel Analytics only.
  Public repo contents are the main exposure (item 3).
- **Maintainability:** one stylesheet per screen, tokens at the page root, dead corkboard code removed today.
  Biggest risk is regressions with no tests (items 5, 6).
